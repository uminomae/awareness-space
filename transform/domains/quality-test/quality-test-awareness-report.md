# ルール評価基準: awareness 報告書 v0.2

**用途**: `transform/domains` の生成物が `awareness` 定義の `domains` を満たすかを判定する  
**判定**: PASS / WARN / FAIL  
**再生成基準**: FAIL が1件でもあれば再生成、WARN 3件以上で再生成検討

---

## A. 主題の正確性

### T1-1: 対象が awareness の `domains` 定義と一致しているか

- レポートが `生存-信頼軸 / 4層モデル / concept notes` のどれかに紐づいているか

### T1-2: 調査問いが明示されているか

- 「この構成要素は何を説明し、何を答えないか」が明記されているか

### T1-3: 範囲外内容の混入がないか

- `D01-D30` 学術領域比較の詳細を主軸に据えていないか（参照目的なら明示）

## B. 構成と可読性

### T2-1: 5W1H が読めるか

- What/Why/Who/When/Where/How のどれかが欠けていないか

### T2-2: 報告書構造

- `§1`（目的）→`§2`（方法）→`§3`（構成要素）→`§4`（知見）→`§5`（限界）→`§6`（結論）を保持しているか

### T2-3: 前提と限界の明示

- 「確定」「暫定」を混在させず、見えていること/見えていないことを分離しているか

## C. 根拠の充実度

### T3-1: evidence 参照

- 根拠のない断定がないか
- 主要主張が evidence 参照（またはその明示）を持つか

### T3-2: 反証可能性

- 条件付き結論には条件を明示しているか

### T3-3: 書きぶり

- 「読者が誤読しやすい比喩」「話し言葉の回想」が過度ではないか

### T3-4: 用語統制

- 同義の用語を別名で混在させていないか
- 同一用語の定義が1箇所で初出されているか

## D. 実務チェック

### T4-1: front matter

以下が存在するか:

- `title`
- `generator_model`
- `lang`
- `version`
- `generated`

### T4-2: パス参照

- レポート内のリンクがローカルで解決可能か
- 既存の `knowledge/`・`evidence/` 構造と競合しないか

## 付録: 実行時コマンド（任意）

```bash
rg -n "d01|d02|d03|academic|領域|領域別" transform/domains/* evidence/* knowledge/*
rg -n "私は|と思う|私の見解" knowledge/domains/*/*.md knowledge/domains/*/*/*.md
```

※ これは参考。evidence の性質により誤検出があるため、目視で補正すること。
