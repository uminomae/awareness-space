# concept audit v0

`awareness-space` の主要ラベルに対する初回の概念監査メモ。

入力:

- `evidence/review/label-first-audit.md`
- `evidence/review/phenomenon-ledger-v0.md`

この文書では、
`Containment`, `生存-信頼軸`, `4層モデル` を
「維持 / 分解 / 保留 / 廃棄」の観点で判定する。

## 1. 判定基準

次の 5 条件を基準にする。

1. 境界: 近縁現象との差が言えるか
2. 反例: このラベルで呼べない例を示せるか
3. 成立条件: 少なくとも 2 つ以上の条件が見えるか
4. evidence 束: 複数 source からの支持があるか
5. 公開安全性: reader-facing に出したとき、確立概念だと誤読されないか

## 2. 監査結果一覧

| ラベル | 判定 | 公開上の扱い | 要点 |
|---|---|---|---|
| Containment | 分解 | 独立 report から降格候補 | P-004〜P-009 を 1語に畳みすぎている |
| 生存-信頼軸 | 保留 | 作業仮説として保持 | 方向づけの区別は有力だが、二軸の最小性は未確定 |
| 4層モデル | 保留 | 構造足場として保持 | source 整理には有効だが、最小記述単位としては未確定 |

## 3. 個別判定

### 3-1. Containment

### 判定

**分解**

### 理由

`phenomenon-ledger-v0` では、
少なくとも次が分離されている。

- P-004: 行動は止まるが問いは開かれない
- P-005: 問いを保持したまま閉じない
- P-006: 内在化された関係が保留可能性を支える
- P-007: 外部化が保持と差分追跡の足場になる
- P-008: 支援者依存でのみ成立する保留
- P-009: 場が保留コストを分散する

現状の `Containment` は、
これらを 1 語の下に置いたまま
「反応を止める技法ではなく、問いを保持する機能」
という定義で reader-facing に出ている。

しかしこの状態では、

- どこからが抑制で、どこからが問い保持なのか
- 凍結や反復固着とどう違うのか
- 他者依存の保留と自立的保留を同じ語でよいのか
- 個人内現象と集団的保留を同じ語でよいのか

が未解決のままである。

### 結論

- `Containment` は独立概念としては**早すぎる**
- 当面は「仮の束名」としてのみ内部保持する
- 公開上は独立 report / manifest card / guide の主要論拠から降格する

## 3-2. 生存-信頼軸

### 判定

**保留**

### 理由

このラベルは、
少なくとも「差異がどういう問題として受け止められるか」を読む仮説としては有力である。

特に、

- 身体的危険や保身へ向かう読み
- 関係的断絶や受容 / 拒絶へ向かう読み

を分ける視点には説明力がある。

一方で、まだ未確定な点が残る。

- 本当に二軸が最小単位なのか
- 信頼軸の中身は信頼 / 愛着 / 所属 / 間主観性のどれが中核なのか
- P-003 の即時短絡と P-006 の関係条件を、同じ軸モデルで扱うべきか

### 結論

- 廃棄する必要はない
- ただし「確立した中核理論」ではなく**作業仮説**として保持する
- 公開上も、検証対象・仮説座標系の表現を維持する

## 3-3. 4層モデル

### 判定

**保留**

### 理由

4層モデルは、

- 身体足場
- 差異の前景化
- 方向づけ
- 反応以前の余地

を切り分ける構造足場としては有効である。

source 整理や読解導線としての価値も高い。

ただし、

- 現象抽出前に 4 層へ当てはめると、構造が先に立つ
- 本当に Layer 0-3 が最小の記述単位なのかは未確定
- P-004〜P-009 を Layer 3 に押し込みすぎる危険がある

### 結論

- 廃棄ではない
- しかし現象そのものではなく、**暫定的な構造足場**として扱う
- 公開上も「意識の最終モデル」ではなく「有力な整理枠」として位置づける

## 4. 暫定命名方針

今は新しい名前を増やさない。

次段階で許されるのは次だけである。

1. 既存ラベルの分解を明示する
2. 新ラベルは evidence 束が揃うまで付けない
3. どうしても便宜上必要な場合は `P-xxx cluster` のような中立表現にする

## 5. `#75` への受け渡し

### 必須変更

1. `Containment` を独立した `report_ready` 構成要素として扱わない
2. guide から「Containment は既に公開済み論拠」という印象を落とす
3. survey で「既存仮説を reader-facing に対応づける」が中心課題だと見せない
4. manifest / reader-rules から concept-first の固定を外す

### 維持可能なもの

1. 生存-信頼軸は仮説として残す
2. 4層モデルは整理枠として残す
3. 原著文書群と concept notes は source bundle として残す

## 6. 暫定結論

初回監査の結論は単純である。

- `Containment` は**分解**
- `生存-信頼軸` は**保留**
- `4層モデル` は**保留**

つまり、
最も強く壊すべきなのは `Containment` の独立性であり、
最も慎重に残すべきなのは `生存-信頼軸` と `4層モデル` の仮説性である。
